# 社区共享工具租赁系统 · 技术方案（前端 + 后端）

> 日期：2026-10-02 ｜ 依据：`docs/PRD.md`、`docs/附录.md`（三张单据字段模板）、`infra/db/schema.sql`（已定稿表结构）
> 原则：在现有单体多模块骨架上做增量设计，不为 Demo 引入 PRD 之外的复杂度。

---

## 1. 方案概述

- **架构形态**：前后端分离的单体应用。后端 = Spring Boot 3.5 单体多模块（已搭好骨架：common 底座 + 6 个业务模块 + boot 聚合）；前端 = Vue 3 + Vite + Element Plus SPA。
- **基础设施**：PostgreSQL 16 + pgvector、Redis 7、RabbitMQ 4.1（延迟消息插件）、MinIO（S3 协议），均已由 `infra/docker` 提供，端口 = 默认 + 1000。
- **覆盖 PRD 六大模块**：工具信息、租赁预约、租赁记录、损坏报修、消息提醒、AI 问答助手；三级权限（居民 / 工作人员 / 管理员）贯穿全部接口。

## 2. 总体架构

见 `docs/diagrams/architecture.html`。要点：

- 浏览器 → 后端仅走 `/api` 前缀 REST 接口，dev 由 Vite 代理（5800 → 8800），生产由 Nginx 反代并终结 HTTPS。
- 后端单体内按业务模块分包，模块间**禁止横向依赖**；跨模块读取走各自 service 接口（如 rental 需要工具信息时调用 tool 模块的 `ToolService`），实体全部下沉 common。
- 消息提醒的**延迟触发**（取件/到期/逾期）走 RabbitMQ 延迟交换机；即时触发（报修确认、维修完成）由业务代码同步调用消息服务。

## 3. 后端设计

### 3.1 模块职责

| 模块 | 职责 | 主要表 |
|---|---|---|
| toolshare-system | 登录认证、三级权限、用户管理、全局配置 | sys_user, sys_config |
| toolshare-tool | 工具录入/审核/查询、分类、编码规则、状态机与日志、图片 | tool_info, tool_category, tool_image, tool_status_log |
| toolshare-rental | 时段校验、预约、模拟支付、取消/取件/归还验收、租赁记录、Excel 导出 | rental_order, pay_record |
| toolshare-repair | 损坏报修、核验、维修进度、修后验收、凭证图片 | repair_order, repair_progress, repair_image |
| toolshare-message | 提醒的发送/存档/查询，站内信 + 短信双通道（不依赖业务模块，延迟触发的消费方在各业务模块） | msg_record |
| toolshare-assistant | 知识库文档上传/解析/切片/向量化、RAG 问答 | kb_document, kb_chunk |
| toolshare-common | 实体、Result/PageResult、BizException、AES TypeHandler、脱敏工具、S3Client 配置、全局常量 | — |
| toolshare-boot | 启动类、application.yml、全局异常、Sa-Token 拦截器注册、@Configuration 汇总 | — |

依赖方向保持现状：业务模块 → common → boot 聚合。**新增例外**（谁需要谁声明，保持无环）：`rental → tool`（改工具状态/写日志）、`rental → message`（提醒发送）、`repair → tool`、`repair → message`、`assistant → system`（配置读取）；message 只被依赖、不依赖任何业务模块，tool / system 不依赖业务模块。

### 3.2 通用约定（复用现有骨架，不再重复造）

- **响应信封**：`Result<T>`（code=`A200`/`C4xx`/`S500`），分页 `PageResult.of(page)`；业务错误一律 `throw new BizException(...)`，由 boot 的 `GlobalExceptionHandler` 兜底，controller 不 try-catch。
- **认证**：Sa-Token。`POST /api/auth/login` 校验密码（BCrypt）后 `StpUtil.login(userId)`，前端保存 token 放 `Authorization` 头；会话存 Redis（`sa-token-redis-template` 已配）。`GET /api/auth/me` 返回当前用户信息 + 角色。
- **鉴权**：接口方法上用 `@SaCheckRole({"STAFF","ADMIN"})` / `@SaCheckRole("ADMIN")` 注解声明角色；boot 注册 `SaInterceptor`（`/api/**` 全拦截，排除 `/api/auth/login`）。越权 → 全局异常处理转 `C403`。
- **参数校验**：DTO 上 `@NotNull/@NotBlank/@Size` + controller `@Validated`，失败信息由现有异常处理器返回第一条字段错误。
- **审计字段**：`MybatisMetaObjectHandler` 已自动填充 create_time/update_time。
- **逻辑删除**：本系统为社区资产台账，不做物理删除与逻辑删除（用户停用走 status=DISABLED）；删除接口仅管理员可用于分类等弱关联数据。

### 3.3 数据模型与状态机

表结构以 `infra/db/schema.sql` 为唯一事实来源（14 表，含 pgvector），实体已全部就位于 common。以下为**状态机**——所有状态流转必须经过对应 service 方法，流转时同步写 `tool_status_log`（工具状态）或补充单据字段，禁止前端直接提交状态值。

**tool_info.status**（工具业务状态）

```
AVAILABLE ──预约成功──► RESERVED ──取件──► IN_USE ──归还验收──► AVAILABLE
    │                                              │
    │◀──────维修验收通过（重新上架）──────────┐      │损坏报修核验通过
    │                                      │      ▼
    └──报废（管理员，验收 FAIL/严重损坏）◄── REPAIRING ◄─┘
```

**rental_order.status**：`PENDING_PAYMENT → RESERVED → PICKED_UP → RETURNED`；支线：`PENDING_PAYMENT → CANCELLED`（支付超时/用户取消）、`RESERVED → CANCELLED`（取件前 24h 外）、`PICKED_UP → OVERDUE`（到期未还的标记态，归还动作仍走 RETURNED）。
**deposit_status**：`UNPAID → PAID → REFUNDING → REFUNDED`（取消或归还结算时进入 REFUNDING，模拟退款成功即 REFUNDED）。
**repair_order.status**：`SUBMITTED → CHECKING(疑似，可选) → CONFIRMED → WAITING_PARTS(可选) → REPAIRING → FINISHED → ACCEPTED`；核验不通过 `SUBMITTED → REJECTED`。
**tool_info.audit_status**：`PENDING → APPROVED / REJECTED`（录入后待审核，APPROVED 且 status=AVAILABLE 才对居民可见可预约）。

### 3.5 关键技术设计

**① 编码规则（附录口径）**
- 工具：`SQ-G-{category.code}-{4 位序号}`，序号取该类别下 max+1；分类 code 复用种子数据（REPAIR/GARDEN/CLEAN/ELECTRIC），不限定两位。
- 租赁单：`SQ-ZY-YYYYMMDD-XXXX`；报修单：`SQ-BX-YYYYMMDD-XXXX`（按当日流水）。
- 实现：common 提供 `CodeGenerator.next(prefix/category, mapper)`——Redisson 锁 `code:{前缀}:{类别或日期}` + `SELECT MAX` +1；数据库唯一约束兜底，锁内冲突重试一次。

**② 预约时段冲突校验（PRD 核心卖点）**
- 校验 SQL：`SELECT count(*) FROM rental_order WHERE tool_id=? AND status IN ('RESERVED','PICKED_UP','OVERDUE') AND start_time < :end AND end_time > :start`，>0 即冲突。
- 生成预约在 Redisson 锁 `lock:tool:{toolId}` 内进行（校验+插入原子化），防并发重复预约；锁等待 3s，失败抛 C409「时段被抢约」。
- 冲突推荐：自请求 start_time 起、当日 30 分钟步进向后探测，找到第一个无重叠且 ≤ 当日 22:00 的时段返回（最多探测 16 次）。
- `GET /availability` 返回当日已占时段数组，前端时间选择器禁用冲突段。

**③ 延迟消息（取件/到期/逾期三类提醒）**
- 交换机 `msg.delay.exchange`（x-delayed-message=direct，compose 已挂插件），队列 `msg.remind.queue`。**@RabbitListener 放在 rental 模块**（它拥有 rental_order，消费时需复核订单状态，且避免 message ↔ rental 循环依赖），复核通过后调 message 模块的 `MsgService.send()` 落库存档。
- 预约支付成功后一次投递三条延迟消息：取件提醒（delay = start_time − 1h）、到期提醒（delay = end_time − 1d）、逾期标记（delay = end_time + 1h），消息体 `{type, orderId}`，header `x-delay=毫秒`。
- 消费端**幂等 + 状态复核**：先按 `biz_code+type` 查 msg_record 判重，再核对订单当前状态（已归还/已取消则丢弃）；通过后调 `MsgService.send()` 落库存档并按渠道发出。
- 兜底：`@Scheduled(cron = "0 0 1 * * ?")` 每日扫描 OVERDUE 漏标订单补状态（MQ 丢失时的自愈）。
- 即时提醒（报修确认/维修完成）：业务事务提交后同步 `MsgService.send()`，不经 MQ。

**④ 押金 / 逾期费 / 退押金结算**
- 支付：`PayService.mockPay()` 写 pay_record（DEPOSIT/REFUND/REPAIR_FEE），状态直接 SUCCESS，模拟沙箱。
- 逾期费 = `ceil(逾期小时数 / 24) × sys_config('overdue_fee_per_day')`，上限 = 押金总额（附录口径）。
- 归还结算：`refund = deposit − overdue_fee − compensation_fee`（下限 0）；写 REFUND 流水，deposit_status=REFUNDED。
- 报修维修费（PRD 模拟支付）：验收时可选录入 repair_fee 并写 REPAIR_FEE 流水；非人为损坏由社区承担（fee=0），仅作台账。

**⑤ 加密存储与脱敏展示（PRD 安全要求）**
- common 提供 `AesTypeHandler extends BaseTypeHandler<String>`：入库 AES 加密（密钥 `security.aes-key`，Hutool SecureUtil.AES），查询自动解密；`phone`/`id_card` 字段应用。
- 出口脱敏在 **DTO 层**（服务端是安全边界）：`MaskUtil.mobile()` / `idCard()`（Hutool DesensitizedUtil）——任何列表/详情接口返回的都是脱敏值，仅 STAFF/ADMIN 在办理业务时可看中段（仍脱敏中间四位，前端不做反查功能，符合 PRD 合规条款）。
- 传输加密：生产 Nginx 终结 HTTPS（押金等财务数据传输安全），应用内不做二次加密。

**⑥ S3 文件上传（后端中转）**
- common `S3Config` 按 `s3:` 段构建 `S3Client`；`FileStorageService.upload(MultipartFile, dir)` 校验类型（jpg/png/mp4）与大小（图 ≤5MB、凭证视频 ≤20MB），对象键 `{dir}/{uuid}.{ext}`，putObject 后返回访问 URL 存表（tool_image / repair_image / kb_document.file_url）。Demo 规模选后端中转，不引入预签名直传的复杂度。

**⑦ RAG 问答（预留式实现）**
- 解析：Apache Tika 抽取 PDF/DOCX/TXT 纯文本（唯一新增解析依赖）。
- 切片：按段落聚合至 ~500 字符、50 字符重叠，写 kb_chunk（tool_id 回填手册归属）。
- 向量化与生成抽象为 common 风格的接口：`EmbeddingClient.embed(List<String>)`、`LlmClient.chat(system, user)`，默认实现为 OpenAI 兼容 HTTP（RestClient 调 `${ai.endpoint}/embeddings`、`/chat/completions`，yml 配置 endpoint/model/api-key，未配置时启动不报错）。
- 问答流程：问题 embedding → pgvector 余弦检索 `ORDER BY embedding <=> :vec LIMIT 5`（MyBatis XML 自定义 SQL，阈值 0.35）→ 拼接片段为上下文调 LLM（system 提示词限定"仅依据资料回答，附来源"）→ 返回 `{answer, sources:[{docName, content}]}`。
- 降级：AI 未配置 → BizException「AI 服务未配置，请联系管理员」；文档 embedding 失败 → kb_document.status=FAILED 可重试。

**⑧ Excel 导出**
- EasyExcel 按 `RentalRecordExportRow`（@ExcelProperty 中文表头对齐附录·租赁记录单字段）写 response 输出流，同分页筛选条件、上限 1 万行。

### 3.6 测试策略

- **必须单测**（纯逻辑，JUnit5 + Mockito，不依赖容器）：时段重叠判定与推荐算法、逾期费计算（含上限）、退押金结算、编码生成器、脱敏工具、文档切片。
- **上下文测试**：保留 `ToolShareApplicationTests`（Spring 上下文 + 数据源连接冒烟）。
- **联调验证**：按 PRD 主链路手工走查（录入→审核→预约→支付→取件→逾期→归还→报修→维修→验收→提醒存档），SQL 落库结果与附录单据字段一一对应。

### 4.3 权限控制（双层）

- **路由层**：`meta.roles` + 全局前置守卫（未登录跳 /login；角色不符跳 /tools + 提示）。
- **视图层**：`useAuth()` composable 暴露 `hasRole(...)`，模板 `v-if` 控制操作按钮（如审核按钮仅 ADMIN）。
- **后端为最终边界**：前端权限仅为体验，所有接口角色校验以 `@SaCheckRole` 为准（防绕过）。

### 4.4 关键交互

- **时段选择**：详情页拉 availability，TimeSlotPicker 渲染 30min 粒度格子，已占灰色禁用；提交冲突时展示后端返回的推荐时段一键填入。
- **状态呈现**：StatusTag 统一映射（如 OVERDUE=danger、REPAIRING=warning、AVAILABLE=success），与附录单据口径一致。
- **归还验收表单**：验收结果三档（完好/轻微/严重）联动：严重必填 compensation_fee，并联动损坏程度重估下拉，提交后即时展示押金退还试算。
- **响应式**：Element Plus 栅格 + MainLayout 侧栏在 <768px 折叠为抽屉；表格页横表给移动端提供卡片变体（仅工具广场/我的租赁两页，管理端按 PC 优先）——满足 PRD"响应式适配"且不做双端开发。

## 5. 安全设计对照（PRD 技术要求）

| PRD 要求 | 方案 |
|---|---|
| 身份证/手机号加密存储 | AesTypeHandler（AES，密钥 yml 注入不入库） |
| 敏感数据脱敏展示 | DTO 出口 MaskUtil 脱敏，全链路不返回明文中段，无反查接口 |
| 三级权限 + 防越权 | @SaCheckRole 注解 + SaInterceptor；本人数据接口强制 `user_id = StpUtil.getLoginIdAsLong()` 条件 |
| 财务数据传输安全 | 生产 HTTPS（Nginx 终结）；模拟支付不出真实资金 |
| 合规（个保法） | 不存储身份证住址等超出必要项；日志打印走脱敏值 |
| 稳定性 | 预约锁 + MQ 幂等 + 定时兜底 + 全局异常兜底 |

## 6. 与 PRD 的偏差与预留（明确记录，非遗漏）

| 项 | PRD 口径 | 本方案 | 理由 |
|---|---|---|---|
| 数据库 | 可选 MySQL | PostgreSQL 16 | pgvector 是 RAG 刚需，MySQL 无原生向量能力 |
| 支付 | 支付沙箱模拟 | PayService.mockPay 直接成功 | 无真实沙箱可用，流水表结构已按真实支付预留 |
| 短信 | 短信通知 | SmsSender 接口 + 日志实现 | 运营商签名未申请；接口不变，接入即换实现 |
| AI | LLM API | OpenAI 兼容 HTTP 客户端 | 兼容主流国内大模型网关；未配置时功能降级不阻塞 |
| 移动端 | 响应式适配 | 栅格 + 关键页卡片变体 | 不做原生/独立 H5，满足"可访问"即可 |

## 7. 实施里程碑（建议顺序，模块间可并行）

1. **底座**：Sa-Token 拦截器注册、AesTypeHandler、MaskUtil、CodeGenerator、S3Config + FileStorageService（common/boot）。
2. **system**：登录/me/用户管理/全局配置 → 前端登录页 + MainLayout + 路由守卫 + request 封装（前后端在此打通鉴权闭环）。
3. **tool**：录入/审核/列表筛选/详情/图片/状态机 → 前端工具广场 + 工具管理。
4. **rental**：availability/预约锁/支付/取消/取件/归还结算/导出 + 延迟消息投递 → 前端预约与我的租赁 + 管理端验收/导出。
5. **repair**：报修→核验→维修→验收全链 + 凭证 → 前端两端报修页。
6. **message**：消费端幂等落库 + 消息中心 + 定时兜底。
7. **assistant**：Tika 解析切片、Embedding/LlmClient、检索问答 → 前端对话页。
8. 每步收尾：`./mvnw test` + 按 3.6 联调清单走查。
