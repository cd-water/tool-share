## 4. 主要开发内容

### 4.1 后端

- 10 个业务模块：认证、工具、租赁与结算、损坏报修、消息、知识库、AI、统计、评价、信用分。
- 租赁、工具、报修均使用显式状态机；关键流转使用条件更新与版本号，避免并发覆盖。
- 押金、逾期费、损坏赔偿、退款拆分到费用明细与支付流水，金额只由服务端计算。
- 待支付 30 分钟自动取消；取件前 24 小时外允许取消；逾期费 5 元/小时，封顶押金。
- 报修支持核验、维修、验收三阶段，并与工具状态同步。
- 消息使用 `biz_key` 幂等；提醒使用 Redis ZSet 调度；关闭提醒不影响业务规则。
- 身份证 AES/GCM 加密；上传图片白名单、真实类型校验与重编码。

### 4.2 前端

- 居民端：工具广场、工具详情、预约支付、我的租赁、损坏报修、消息中心、AI 助手、个人中心。
- 管理端：仪表盘、工具管理、租赁管理、报修管理、知识库、消息中心、管理员账号。
- 双端类型来自 OpenAPI 契约生成，避免手写枚举漂移。
- 统一间距标尺与栅格：桌面 4 列、1100 以下 2 列、680 以下 1 列；AI 与个人中心侧栏在窄屏堆叠；管理端表格内部滚动，不撑破页面。
- 1440 / 1024 / 390 宽度逐页检查，无横向溢出。

### 4.3 AI 与数据

- 知识库文档解析、切块、向量索引状态可追踪；失败自动重试。
- 问答先向量检索，异常或无命中降级关键词检索；SSE 先发来源，再流式回答。
- 回答带 `[n]` 引用，来源标题与片段可定位。
- 推荐记录推荐单，点击与反馈写入 `t_ai_recommendation`；降级时 `degraded=true`。
- 固定评测集输出检索命中率与引用准确率，默认阈值 0.8。

### 4.4 初始化与运维

- 迁移拆分为 V1–V4 纯建表脚本，演示数据与测试数据独立。
- 空库启动自动写入演示数据：2 个居民、1 个管理员、8 件工具、28 篇知识库文档。
- 启动时上传工具图片、头像与登录背景，设置 MinIO 公开读并回填直链。
- 启动时校准 Redis 单号序列，避免种子编号与后续新建冲突。
- `ops/verify.sh` 串联后端测试、双端 lint/构建与 E2E。

## 6. 关键问题与解决

| 问题 | 影响 | 解决 |
| --- | --- | --- |
| 先查冲突再插入会并发重复预约 | 同一工具同一时段出现两张单 | 工具行锁 + 条件更新 + 冲突查询 |
| 整行覆盖更新覆盖资金/状态事实 | 押金与状态不一致 | 条件更新、版本号、费用明细与支付流水 |
| 待支付单永不过期 | 档期被长期占用 | 30 分钟超时任务 + 原子取消 |
| 报修与归还竞态 | 损坏责任悬空 | 锁定租赁行；未完成报修阻止直接归还 |
| 上传可直出 HTML/SVG | 同源存储型 XSS | 白名单、真实类型校验、图片重编码、`nosniff` |
| AI 外部服务不可用 | 问答/推荐阻塞主流程 | 关键词降级、兜底回答、`degraded` 标识 |
| 种子导入中文乱码 | 工具与知识库显示异常 | 统一 `utf8mb4` 客户端字符集 |
| 图片经后端代理，流量集中 | 与真实对象存储用法不一致 | 公开桶直链 + `MINIO_PUBLIC_ENDPOINT` + 代理兜底 |
| 窄屏固定列数导致溢出 | 管理端知识库页面横向撑破 | 栅格断点、表格内部滚动、侧栏堆叠 |

## 8. 风险与应对

| 风险 | 应对 |
| --- | --- |
| 外部 AI 服务不可用 | 默认降级路径；评测集独立运行；不把 AI 放入主流程失败链路 |
| 课程环境资源有限 | 单实例部署；Docker Compose 统一中间件；提供 `SKIP_E2E` |
| 演示数据被误改 | 空库自动种子；重复启动不重复写入；演示数据与测试数据分离 |
| 权限越权 | 双账号体系 + 角色权限 + 数据归属校验 + 集成测试 |
| 前端契约漂移 | OpenAPI 契约生成类型；删除手写枚举与旧接口 |

## 9. 当前状态与后续工作

当前系统已完成课程要求的主流程、管理端能力与三项扩展亮点，处于可演示、可验收状态。

后续可选工作：

3. 多实例部署下的分布式调度与提醒锁。
4. 增加管理员操作审计表与导出审计报表。
5. 扩充 AI 评测集，覆盖更多工具安全与费用问题。

## 10. 总结

项目按迭代方式完成了从需求、设计、开发、测试到部署交付的完整过程。核心业务通过状态机、条件更新和流水记录保证一致性；双端页面完成真实接口接入；AI 能力具备引用溯源与降级路径；测试与一键验证保证交付质量。当前版本满足课程验收要求，并保留了清晰的后续扩展边界。
