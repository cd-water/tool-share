# 社区共享工具租赁系统需求说明书

## 1. 文档说明

### 1.1 编写目的

本文档将课程原始需求 `docs/PRD.md` 转化为可设计、可开发、可测试、可验收的需求说明，明确系统边界、角色权限、业务规则、数据约束与验收标准，作为开发、测试和交付的共同依据。

### 1.2 适用范围

适用于社区共享工具租赁系统的课程设计、开发实现、测试验收与答辩演示。系统包含居民端、管理端、后端服务、对象存储与 AI 检索能力。

### 1.3 术语

| 术语 | 含义 |
| --- | --- |
| 工具 | 社区所有、可供居民租赁的单件实物 |
| 租赁单 | 居民对某件工具的一次完整租用，从预约、支付、取件、使用到归还验收 |
| 押金 | 居民为租赁单预付的担保金额，归还验收后按费用结算退还 |
| 费用明细 | 租赁单上由服务端计算的逾期费、损坏赔偿与减免条目 |
| 支付流水 | 押金收取、退款与补收的资金事实记录 |
| 报修单 | 居民就一张使用中的租赁单提交的损坏处理请求 |
| 核验 / 验收 | 工作人员确认报修是否成立，或确认归还/维修结果是否可用 |
| 评价 / 信用分 | 居民对已归还租赁单的反馈，以及按履约事件加减的信用记录 |
| 提醒偏好 | 居民按消息类型设置的接收渠道与开关 |

## 2. 项目概述

### 2.1 项目背景

社区居民对维修、园艺、清洁等工具存在“偶尔用、购买贵”的需求。社区已购置部分共享工具，但人工登记、口头预约、纸质验收容易产生重复预约、押金纠纷、逾期未还、损坏责任不清等问题。

### 2.2 建设目标

1. 将工具信息、预约、押金、取件、归还、报修、提醒纳入统一系统。
2. 通过状态机、条件更新与流水记录保证租赁和资金事实可追溯。
3. 为居民提供低门槛的预约、报修、消息与 AI 咨询入口。
4. 为工作人员提供工具、租赁、报修、知识库与账号管理能力。
5. 通过自动化测试与一键验证保证交付质量。

### 2.3 系统边界

**包含**：居民端、管理端、后端 API、MySQL、Redis、MinIO、Qdrant、Ollama、DeepSeek 问答、演示数据与初始化脚本。

**不包含**：真实短信通道、真实支付渠道、居民信息系统对接、视频报修、多实例调度、CI/CD 流水线、生产反向代理配置。

## 3. 用户角色与权限

### 3.1 角色定义

| 角色 | 入口 | 主要职责 |
| --- | --- | --- |
| 居民 USER | 居民端 `frontend/web` | 浏览工具、预约支付、取件归还、报修、消息、AI、评价与信用分 |
| 工作人员 STAFF | 管理端 `frontend/admin` | 取件、归还验收、租赁查询导出、报修核验/维修/验收、消息、仪表盘 |
| 系统管理员 SUPER_ADMIN | 管理端 `frontend/admin` | 工作人员全部能力，另含工具审核、知识库、管理员账号与渠道配置 |

### 3.2 权限矩阵

| 能力 | 居民 | 工作人员 | 系统管理员 |
| --- | :---: | :---: | :---: |
| 浏览工具与可预约时段 | ✓ | — | — |
| 创建/支付/取消本人租赁单 | ✓ | — | — |
| 查看本人租赁、报修、消息、评价、信用分 | ✓ | — | — |
| 查询全部租赁单并导出 Excel | — | ✓ | ✓ |
| 确认取件、归还验收、登记费用 | — | ✓ | ✓ |
| 报修核验、维修进度、维修验收 | — | ✓ | ✓ |
| 查看管理端仪表盘 | — | ✓ | ✓ |
| 工具新增/编辑/审核/状态/历史日志 | — | — | ✓ |
| 知识库上传、删除、索引状态 | — | — | ✓ |
| 管理员账号与角色管理 | — | — | ✓ |
| 消息渠道与默认提醒配置 | — | — | ✓ |

补充约束：

1. 居民端与管理端使用 sa-token 两套账号体系，token 不得混用。
2. 居民数据按归属校验，不能查看或操作他人租赁单与报修单。
3. 工作人员不能访问工具台账、知识库和管理员账号接口。
4. 身份证号 AES/GCM 加密存储，接口只返回脱敏值；手机号在管理端按需脱敏展示。

## 4. 总体业务流程

### 4.1 租赁主流程

```text
浏览工具 → 选择时段 → 创建租赁单 → 30 分钟内支付押金
→ 工作人员确认取件 → 居民使用 → 按时归还
→ 工作人员验收 → 结算逾期费/损坏赔偿 → 退还押金
```

关键规则：

- 创建租赁单前必须完善真实姓名与身份证号。
- 开始时间必须晚于当前时间，结束时间必须晚于开始时间。
- 已预约、使用中、已逾期、未超时的待支付租赁单均占用档期。
- 待支付超过 30 分钟自动取消并释放档期。
- 取件前 24 小时以外居民可自助取消；不足 24 小时联系工作人员。
- 逾期费按每小时 5 元计算，最高不超过押金。
- 金额只由服务端计算，费用写入费用明细与支付流水。

### 4.2 租赁状态

```text
PENDING_PAYMENT（待支付）
  ├─ 支付 → RESERVED（已预约）→ PICKED_UP（使用中）→ RETURNED（已归还）
  ├─ 取消 → CANCELLED（已取消）
  └─ 超时 → CANCELLED（自动取消）

PICKED_UP → OVERDUE（已逾期）→ RETURNED
RESERVED → CANCELLED（取件前 24 小时外）
```

### 4.3 报修流程

```text
居民提交报修（SUBMITTED）
→ 工作人员核验：VERIFIED / REJECTED
→ 维修：REPAIRING
→ 维修完成：COMPLETED
→ 验收：合格恢复工具 / 继续维修 / 报废 SCRAPPED
```

同一租赁单只能存在一张未完结报修单；存在未处理报修时，归还流程需要先完成核验与验收。

## 5. 功能需求

### FR-01 认证与账号

| 编号 | 需求 |
| --- | --- |
| FR-01-01 | 居民支持手机号 + 验证码登录，首次登录自动创建账号 |
| FR-01-02 | 居民支持手机号 + 密码登录；未设置密码的账号只能验证码登录 |
| FR-01-03 | 验证码 5 分钟有效、一次性消费；连续错误达到上限后失效 |
| FR-01-04 | 发送验证码受手机号分钟/小时与 IP 小时频控 |
| FR-01-05 | 居民可维护昵称、头像、真实姓名与身份证号；预约前必须完成实名 |
| FR-01-06 | 身份证加密存储，页面只展示脱敏值 |
| FR-01-07 | 管理端支持管理员账号登录，角色为 STAFF 或 SUPER_ADMIN |
| FR-01-08 | 被禁用账号不能登录，已登录会话在后续请求中被拒绝 |

验收要点：验证码错误/过期/重放被拒绝；并发消费同一验证码只成功一次；禁用账号被拦截；身份证接口不返回明文。

### FR-02 工具信息管理

| 编号 | 需求 |
| --- | --- |
| FR-02-01 | 工具编码按类别自动生成，格式如 `SQ-G-WX-0001` |
| FR-02-02 | 工具包含名称、型号、类别、损坏程度、状态、押金、存放区域、图文使用说明、图片、采购信息 |
| FR-02-03 | 工具审核状态为待审核/已通过/需修改；只有已通过工具可预约 |
| FR-02-04 | 工具状态为可预约/租赁中/维修中/已报废，状态变更写入工具日志 |
| FR-02-05 | 居民端支持按名称、型号、编码模糊查询，按类别、状态、排序筛选 |
| FR-02-06 | 管理端支持按编码、存放区域、租赁次数、最近维修时间筛选 |
| FR-02-07 | 工具详情展示使用说明、押金、历史租赁摘要与评价摘要 |
| FR-02-08 | 居民可对不可租工具登记蹲守，工具恢复可租时收到提醒 |

验收要点：重复工具编码被拒绝；未审核工具不可预约；状态机不允许非法跳转；日志含操作人、前后状态与时间。

### FR-03 租赁预约与支付

| 编号 | 需求 |
| --- | --- |
| FR-03-01 | 居民选择工具与起止时间，系统展示可预约时段 |
| FR-03-02 | 时段冲突时返回明确提示与最近可预约建议 |
| FR-03-03 | 创建租赁单需填写取件人并选择到期提醒提前量 |
| FR-03-04 | 创建成功后生成唯一租赁单号，状态为待支付 |
| FR-03-05 | 押金金额取工具预设值，支付后状态变为已预约 |
| FR-03-06 | 待支付超过 30 分钟自动取消并释放档期 |
| FR-03-07 | 取件前 24 小时外居民可取消；已支付押金记录退款 |
| FR-03-08 | 并发预约同一工具同一时段时，只允许一个请求成功 |

验收要点：冲突时段被拒绝；支付超时后不可支付；并发测试只生成一张有效租赁单；取消后档期释放。

### FR-04 租赁记录与结算

| 编号 | 需求 |
| --- | --- |
| FR-04-01 | 居民可查看本人全部租赁单，支持分页与状态筛选 |
| FR-04-02 | 工作人员可查看全部租赁单，支持关键词、状态、逾期、验收结果筛选 |
| FR-04-03 | 工作人员确认取件后租赁单进入使用中；逾期后标记逾期 |
| FR-04-04 | 归还时登记实际归还时间、验收结果、备注与减免原因 |
| FR-04-05 | 系统计算逾期费、损坏赔偿、退款，并写入费用明细与支付流水 |
| FR-04-06 | 赔偿超过押金时记录应收，不以退款掩盖差额 |
| FR-04-07 | 工作人员可将筛选结果导出 Excel |

验收要点：金额由服务端计算；费用与流水可追溯；赔偿超额有应收记录；导出字段与列表一致。

### FR-05 损坏报修

| 编号 | 需求 |
| --- | --- |
| FR-05-01 | 居民可对使用中或逾期的租赁单提交报修，填写部位、描述并上传 1–3 张照片 |
| FR-05-02 | 同一租赁单不能重复创建未完结报修 |
| FR-05-03 | 工作人员核验报修，结果为确认损坏或驳回，并记录原因 |
| FR-05-04 | 确认后登记维修负责人、预计时间、维修说明与费用 |
| FR-05-05 | 维修完成后验收，决定工具恢复可租、继续维修或报废 |
| FR-05-06 | 报修进度对居民与工作人员可查，关键节点发送消息 |
| FR-05-07 | 存在未完成报修时，归还流程需要先处理报修 |

验收要点：状态机非法跳转被拒绝；重复报修被拒绝；核验/维修/验收权限正确；工具状态与报修结果同步。

### FR-06 消息提醒

| 编号 | 需求 |
| --- | --- |
| FR-06-01 | 支持预约创建、支付成功、取消、取件、到期、逾期、报修、维修完成、蹲守到货等消息 |
| FR-06-02 | 支持站内消息与 Mock 短信两种渠道，居民可设置提醒偏好 |
| FR-06-03 | 消息记录包含接收人、类型、渠道、送达状态、已读状态与时间 |
| FR-06-04 | 业务消息使用 `biz_key` 幂等，重复触发不产生重复消息 |
| FR-06-05 | 到期提醒按居民设置的提前量调度；提醒任务按单实例设计 |
| FR-06-06 | 居民可查看未读数、单条已读与全部已读 |

验收要点：同一业务事件不重复发送；关闭某类提醒后不再发送；逾期等业务规则不因关闭提醒而取消。

### FR-07 知识库与 AI 问答

| 编号 | 需求 |
| --- | --- |
| FR-07-01 | 管理员可上传 txt/md/pdf/docx 知识库文档，系统解析正文 |
| FR-07-02 | 文档切块后写入向量库，记录索引状态；失败可重试 |
| FR-07-03 | 居民可向 AI 助手提问，系统先检索知识库再流式回答 |
| FR-07-04 | 回答附带 `[n]` 引用，并展示来源标题与片段 |
| FR-07-05 | 向量检索失败、超时或无命中时降级关键词检索 |
| FR-07-06 | 大模型不可用时返回确定性兜底回答，不阻断事件流 |
| FR-07-07 | 提供固定评测集，输出检索命中率与引用准确率 |
| FR-07-08 | 推荐结果记录推荐单，支持点击与“有帮助/没帮助”反馈 |

验收要点：SSE 先发 sources 再逐条发 message；来源可点击定位；降级时页面有提示；评测脚本可独立运行。

### FR-08 评价与信用分

| 编号 | 需求 |
| --- | --- |
| FR-08-01 | 仅本人已归还租赁单可评价，一单一评且不可修改 |
| FR-08-02 | 评分为 1–5 星，支持文字与最多 3 张图片 |
| FR-08-03 | 评分参与工具评分汇总与推荐排序 |
| FR-08-04 | 信用分初始 100，范围 0–100 |
| FR-08-05 | 按时归还 +2、逾期 -3、严重损坏 -10、收到 ≤2 星评价 -5 |
| FR-08-06 | 每次信用变化写入流水，居民可查看原因与时间 |

验收要点：未归还租赁单不能评价；重复评价被拒绝；信用分与流水增量一致；低星评价只计一次。

### FR-09 统计与管理端

| 编号 | 需求 |
| --- | --- |
| FR-09-01 | 用户端展示可借工具、待支付、租借中、未读消息 |
| FR-09-02 | 管理端仪表盘展示工具总数、活跃租赁、逾期预警、待处理报修、分类数量与最近动态 |
| FR-09-03 | 统计口径来自真实业务表，不展示虚构趋势 |
| FR-09-04 | 管理员可查看账号列表并分配 STAFF/SUPER_ADMIN 角色 |
| FR-09-05 | 系统管理员可配置消息默认渠道与 Mock 短信开关 |

验收要点：统计随业务数据变化；角色变更后权限立即生效；工作人员不能访问系统管理员接口。

## 6. 非功能需求

### 6.1 安全

- 密码 BCrypt 存储；身份证 AES/GCM 加密，密钥长度校验。
- 上传文件校验扩展名与真实 MIME，图片重编码后存储；禁止 HTML/SVG 直出。
- 对象存储桶公开读，但只存放重编码后的 JPEG/PNG；`/api/files/**` 作为兜底并设置 `nosniff`。
- 验证码频控、一次性消费、尝试次数上限。
- 所有管理端接口按角色校验；居民接口按数据归属校验。
- 生产环境通过 HTTPS 传输；`ID_CARD_AES_KEY` 必须使用独立密钥。

### 6.2 性能与可靠性

- 列表接口统一分页，避免一次返回全量数据。
- 同一工具并发预约通过行锁 + 条件更新保证互斥。
- 提醒调度使用 Redis ZSet，数据库消息行保证可查询与幂等。
- 外部 AI 服务异常时降级，不阻断租赁主流程。
- 单实例部署假设；多副本需重新设计调度与提醒。

### 6.3 兼容性与可用性

- 桌面端支持 Chrome、Edge、Firefox 等现代浏览器。
- 居民端和管理端支持 1440、1024、768、390 宽度；工具网格、统计卡片、侧栏与表格按断点降级。
- 关键操作有明确提示、错误信息与加载状态；危险操作二次确认。
- 表单字段有标签与校验提示；图片有替代文本。

### 6.4 可维护性

- 后端按业务模块内聚，公共能力集中在 `shared/`。
- 数据库迁移按域拆分为 V1–V4 纯建表脚本，演示数据与测试数据独立。
- 前端类型来自 OpenAPI 契约生成，避免三端枚举漂移。
- 主流程由 Playwright E2E 覆盖，后端由 Testcontainers 集成测试覆盖。

约束：

- 租赁单号、报修单号、工具编码由 Redis 序列生成，启动时按库内最大值校准。
- 金额字段使用 `DECIMAL`，由服务端计算。
- 状态字段使用受控枚举值，禁止前端直接提交非法状态。

## 9. 范围裁剪与扩展亮点

### 9.1 明确裁剪

| 条目 | 处理方式 | 原因 |
| --- | --- | --- |
| 财务字段级加密 | 由部署层 HTTPS 承担 | 应用层加密无法解决传输安全 |
| 数据库备份代码 | 写入运维文档与脚本 | 属于部署职责 |
| 居民信息系统对接 | 不做 | PRD 标注可选 |
| 视频报修 | 仅支持 1–3 张图片 | 控制存储与审核成本 |
| 多实例调度/分布式锁 | 单实例设计 | 课程环境不涉及横向扩容 |
| CI/CD 流水线 | 本地一键验证 | 无托管 CI 环境 |
| 管理员操作审计表 | 仅角色权限 | 不新增审计表 |
| 覆盖率百分比门槛 | 以关键路径测试为准 | 避免数字达标但路径缺失 |

### 9.2 扩展亮点

1. **评价 + 信用分**：评价影响工具排序与推荐，信用分按履约事件可解释地加减。
2. **AI 引用溯源 + 评测集 + 反馈闭环**：回答带来源，固定评测集量化检索质量，推荐点击与反馈可追溯。
3. **主流程 E2E + 一键验证**：三条真实前端流程串行执行，配合 Testcontainers 集成测试。
4. **启动自动种子 + 对象存储直链**：空库启动即可演示，28 篇知识库文档与工具图片自动初始化。
